1. 选题背景与意义

共享单车是城市短途出行的重要组成部分。实际运营中，车辆需求会受到通勤高峰、工作日与周末、天气变化、会员结构、车辆类型和区域功能差异等因素影响，常见问题包括热门站点无车可借、通勤终点车辆堆积、恶劣天气下需求波动明显等。

本项目计划以 Capital Bikeshare 公开骑行记录为主要数据源，并融合 Open-Meteo 历史天气数据，构建一个从数据采集、清洗融合、特征工程、多模型预测到站点调度分析和可视化展示的完整数据挖掘流程。

2. 研究问题与项目目标

项目目标：预测未来小时级骑行需求，识别站点净流出/净流入模式，并将结果转化为可解释的补车和清车建议。
  1. 小时级共享单车需求是否存在稳定的日周期、周周期和季节差异？
  2. 天气变量、会员类型和车辆类型是否能增强需求预测效果？
  3. 传统机器学习模型、集成树模型和 LSTM 时序模型在该任务中的表现有何差异？
  4. 如何基于站点净流入/净流出识别需要补车或清车的重点站点？

3. 数据来源与计划范围

数据类型数据来源计划字段主要用途
骑行记录Capital Bikeshare System Data起止时间、起终点站、车辆类型、会员类型、经纬度构建小时级需求和站点级净需求
历史天气Open-Meteo Historical Weather API温度、相对湿度、降水、风速分析天气对骑行需求的影响
时间特征由骑行开始时间派生小时、星期、月份、周末、周期编码捕捉通勤和周期规律

计划使用 2023-2025 三年骑行记录。若本地计算或下载压力较大，可先运行单年或单月烟测；正式实验统一聚合到小时粒度。

5. 模型与实验设计

模型类别模型设置目的
时间基线Seasonal Naive判断模型是否超过简单周期复制策略
线性模型Ridge Regression检查基础特征的线性解释能力
集成树模型Random Forest、HistGradientBoosting、XGBoost捕捉非线性关系和特征交互
深度时序模型LSTM对比序列建模方法在该任务中的适用性

实验计划采用时间顺序切分：前 80% 时间段作为训练集，后 20% 时间段作为测试集。LSTM 部分计划优先检测 GPU 环境；如果 CUDA 可用，则使用 GPU 训练，否则自动退回 CPU。

8. 风险与应对

风险可能影响应对策略
数据下载或 API 不稳定无法及时获取全部原始数据缓存原始 zip 和处理后 CSV，支持复用已有数据
字段或时间格式不一致清洗流程失败或样本丢失编写字段检查和时间解析测试，必要时按月份兼容处理
全年数据处理较慢训练和演示耗时过长先完成半年版本，再扩展全年；Dashboard 读取离线结果
LSTM 效果不如集成树模型深度模型贡献不明显将其定位为对照实验，分析任务特征与模型适配性
现场演示环境波动Dashboard 无法稳定启动准备静态 HTML 图表、截图和演示视频作为备份

9. 验收标准与预期成果

  1. 数据管道可以从原始骑行数据和天气 API 生成小时级建模表。
  2. 至少完成 5 类模型对比，并输出统一格式的指标和预测文件。
  3. 调度分析能够输出站点净流出/净流入排序、站点聚类画像、Top 20 站点预测和补车/清车建议。
  4. Streamlit Dashboard 可以在本地启动，并加载全部核心图表。
  5. 每名组员都有明确代码模块、文档章节或实验产出。
